## 预生产和生产上线顺序

1. **锁定候选**：记录合并提交 SHA、annotated tag、core 包 SHA256、manifest 中的 commit/source_sha256、Python Agent 镜像 digest、运维脚本来源提交；所有组件对应同一候选。去掉 CHANGELOG 的“开发中”前先完成发布审查。
2. **核对配置**：确认运行身份、应用授权、Go→Python 代理地址、治理回调地址和共享凭据一致；仅记录凭据是否匹配，不把密钥写进验收记录。在线升级执行开关保持现有默认关闭，不因本轮回归通过而自动开启。
3. **一致性备份**：列明 Go 数据/数据库、迁移见证、运行配置与主密钥，以及 Agent 任务 JSON、知识/评测 JSON、检查点 SQLite 的真实路径。停止相关写入或采用一致性快照，不能直接复制正在写入的 SQLite 主文件而遗漏 WAL。
4. **隔离恢复**：将备份恢复到独立数据根，用配置对应的校验工具验证摘要和见证；确认旧任务、历史草案/确认、来源、授权和关联可读。记录备份 ID、SHA256、恢复路径和命令结果。不要覆盖生产新写入。
5. **预生产部署**：先同步同提交的安装器/升级脚本，关闭并发升级；协调 Go 与 Python Agent 升级。验证 readiness 和同源登录，使用专用验收组织/应用检查选择应用→结构快照→草案→人工确认→正式变更及回填。**不自动提交审批、不签发通行证、不执行 SQL。**
6. **故障回滚演练**：仅在隔离预生产环境注入启动失败和 readiness 失败，核对旧核心与配套 Agent 恢复，重新验证登录和旧记录。确认自动脚本不恢复数据；若需要恢复备份，先评估窗口内新增记录并经人工确认。
7. **生产窗口**：使用已验收的不可变制品小流量部署。readiness 必须指向目标实例，不能用其他实例的响应掩盖故障；观察窗口与错误率/延迟阈值由运维在上线前根据现有 SLO 固定，记录基线、部署后数据和告警。
8. **失败退出**：任何核心/Agent 健康失败、授权回归、材料/来源异常或恢复失败，停止扩大流量并按预案回退；保留失败版本和升级后的数据供诊断，不能删除或复写证据来得到成功状态。
