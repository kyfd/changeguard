# ChangeGuard 3.1：可追踪、可验证的变更协作

状态：开发中，未发布。以 v3.0.10 为基线，按可独立验收的里程碑交付，不把第一批功能称为完整 3.1。

## 原则

- 复用已有取消、显式恢复、调用账本、证据引用、材料确认和离线评测，不重做已有能力。
- Agent 只准备材料与解释；模型工具保持只读，审批、通行证和执行仍由确定性后端控制。
- 任务来源不是权限凭据。组织与创建者校验必须在服务端执行。
- 未知费用、未运行的真实模型、模拟证据继续如实标记，不用默认成功值替代。

## M1：任务工作区（本批）

- 服务端搜索（需求、任务 ID、应用）、状态/来源/活跃/归档/回收站筛选。
- 来源由 `AGENT_TASK_SOURCE=production|evaluation|demo` 配置，默认 production；旧记录返回 legacy，不根据标题猜测或批量修改历史数据。
- 默认列表仅 production + legacy，且仅活跃记录；`source=all` 仍只返回同组织、同创建者的数据。
- 归档/恢复持久化且保留事件。归档、回收站记录只读，恢复不调用模型。
- 删除预览绑定完整记录 SHA-256；确认时重新检查资格与摘要，拒绝陈旧预览。
- 本批删除为**可恢复软删除**，保留事件、检查点与用量。仅允许已归档的 FAILED/CANCELLED/INPUT_REJECTED，且无草案、生成痕迹、人工确认或已知正式变更关联。
- 尚无权威跨服务关联索引，采用保守拒绝；不能宣称已经支持任意任务/正式变更的安全物理清理。
- 评测器强制独立 JSON/SQLite 文件和 evaluation 来源，不能由用例覆盖为正式存储。

### API

所有路径以 `/api/agent` 开头，经 Go 同源代理，可信身份与上游凭据规则不变。

| 方法/路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /tasks | q≤200、status、source、workspace | 保持 list[TaskView]，兼容旧数组消费端 |
| POST /tasks/{id}/archive | 无 | TaskView；正在执行则 409 |
| POST /tasks/{id}/restore | 无 | 回收站→归档；归档→活跃，不自动执行 |
| GET /tasks/{id}/delete-preview | 无 | allowed、blockers、record_version、effect、retained |
| POST /tasks/{id}/delete | record_version | TaskView；陈旧摘要或不允许则 409 |

source：default/all/production/evaluation/demo/legacy；workspace：active/archived/trash/all。
TaskView 新增 source、created_at、updated_at、archived_at、deleted_at；旧记录时间缺失保持 null。
跨组织/跨创建者返回 404；缺失身份 401；落盘失败 503，内存状态不得领先磁盘。

### 部署与回滚边界

本批需同时升级 Python Agent 和嵌入前端的 Go 服务。不能只升级前端：旧 Agent 不支持新接口。
发布前备份任务 JSON、检查点 SQLite、Go 数据与迁移见证。当前分支不触碰线上数据。
数据仍为单实例 JSON 原子落盘；软删除不释放磁盘空间，不构成个人数据擦除机制。
回退旧 Python 代码会忽略归档/软删除字段，使这些记录重新可见/可操作；因此使用新生命周期功能后不能无说明地直接降级。回滚需停服务、评估新增数据并从成对备份恢复，不能静默覆盖用户新记录。
