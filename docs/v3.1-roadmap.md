# ChangeGuard 3.1：可追踪、可验证的变更协作

状态：M1、M2、M3 已实现（未合并、未发布）。以 v3.0.10 为基线，按可独立验收的里程碑交付。功能实现完成不代表 v3.1.0 发布门禁通过：生产端到端、真实模型评测与迁移/回滚演练仍未执行。

## 原则

- 复用已有取消、显式恢复、调用账本、证据引用、材料确认和离线评测，不重做已有能力。
- Agent 只准备材料与解释；模型工具保持只读，审批、通行证和执行仍由确定性后端控制。
- 任务来源不是权限凭据。组织与创建者校验必须在服务端执行。
- 未知费用、未运行的真实模型、模拟证据继续如实标记，不用默认成功值替代。

## M1：任务工作区（本批）

- 服务端搜索（需求、任务 ID、应用）、状态/来源/活跃/归档/回收站筛选。
- 来源由 `AGENT_TASK_SOURCE=production|evaluation|demo` 配置，默认 production；旧记录返回 legacy，不根据标题猜测或批量修改历史数据。
- 默认列表仅 production + legacy，且仅活跃记录；`source=all` 仍只返回同组织、同创建者的数据。
- 归档/恢复持久化且保留事件。归档、回收站记录只读，恢复不调用模型。
- 删除预览绑定完整记录 SHA-256；确认时重新检查资格与摘要，拒绝陈旧预览。
- 本批删除为**可恢复软删除**，保留事件、检查点与用量。仅允许已归档的 FAILED/CANCELLED/INPUT_REJECTED，且无草案、生成痕迹、人工确认或已知正式变更关联。
- 尚无权威跨服务关联索引，采用保守拒绝；不能宣称已经支持任意任务/正式变更的安全物理清理。
- 评测器强制独立 JSON/SQLite 文件和 evaluation 来源，不能由用例覆盖为正式存储。

### API

所有路径以 `/api/agent` 开头，经 Go 同源代理，可信身份与上游凭据规则不变。

| 方法/路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /tasks | q≤200、status、source、workspace | 保持 list[TaskView]，兼容旧数组消费端 |
| POST /tasks/{id}/archive | 无 | TaskView；正在执行则 409 |
| POST /tasks/{id}/restore | 无 | 回收站→归档；归档→活跃，不自动执行 |
| GET /tasks/{id}/delete-preview | 无 | allowed、blockers、record_version、effect、retained |
| POST /tasks/{id}/delete | record_version | TaskView；陈旧摘要或不允许则 409 |

source：default/all/production/evaluation/demo/legacy；workspace：active/archived/trash/all。
TaskView 新增 source、created_at、updated_at、archived_at、deleted_at；旧记录时间缺失保持 null。
跨组织/跨创建者返回 404；缺失身份 401；落盘失败 503，内存状态不得领先磁盘。

### 部署与回滚边界

本批需同时升级 Python Agent 和嵌入前端的 Go 服务。不能只升级前端：旧 Agent 不支持新接口。
发布前备份任务 JSON、检查点 SQLite、Go 数据与迁移见证。当前分支不触碰线上数据。
数据仍为单实例 JSON 原子落盘；软删除不释放磁盘空间，不构成个人数据擦除机制。
回退旧 Python 代码会忽略归档/软删除字段，使这些记录重新可见/可操作；因此使用新生命周期功能后不能无说明地直接降级。回滚需停服务、评估新增数据并从成对备份恢复，不能静默覆盖用户新记录。

## M2：执行轨迹与草案版本（本批）

- **执行轨迹**：从已落盘的事件、工具观察与调用账本投影出逐步视图（步骤、状态、实测耗时、
  引用、token、费用、失败原因）。**不含模型内部思维链**；未记录的耗时 / token / 费用保持
  未知（null），不用 0 冒充；未知项在 `unknown` 中显式列出。
- **草案版本快照**：每次生成或服务端编辑都追加一份不可变快照（版本、来源、修改人、时间、
  原因、SQL/回滚、内容摘要、检查结论、引用）。服务端用统一 diff 计算 SQL 与回滚差异。
- **服务端版本化编辑**：校验组织 + 创建者 + 任务状态 + `expected_version`；拒绝并发覆盖、
  陈旧页面与越权；编辑后**重新执行确定性检查**（不使用其他内容的检查结果）；检查未通过或
  扫描工具失败即失败关闭（落到 `CHECK_BLOCKED`）；旧确认失效但审计与旧版本保留。
- **等外部 I/O 的写入以最新记录为准**：编辑、关联、恢复在等待（确定性扫描 / 治理核对 / 读检查点）
  之后**重新读取记录**，重新校验生命周期与版本，并只在最新记录上合并写入。等待期间并发的归档、
  关联与审计不会被旧记录覆盖；恢复的输入变更（槽位/快照/补充说明）合并到最新记录后再落盘。
- **服务端权威关联 + 幂等创建**：Go `POST /api/changes` 支持 `Idempotency-Key`（持久化幂等
  记录），重复点击 / 并发 / 超时重试 / 进程重启后的重试都返回同一个变更单；变更单记录
  服务端判定的 `source`（console / agent_task）与 `agent_task_id`，可双向核对。
  Agent 侧 `POST /tasks/{id}/change-links` 先经治理只读接口核对变更存在且属于本组织，
  失败关闭，且同一变更 / 幂等键重复提交是幂等的。
- **只读边界相容**：归档 / 回收站任务对新接口同样只读，不能借新接口绕过生命周期限制。

| 方法/路径 | 请求 | 响应 |
| --- | --- | --- |
| GET /tasks/{id}/trace | 无 | TaskTrace：steps、usage、unknown、includes_model_reasoning=false |
| GET /tasks/{id}/draft/versions | 无 | list[DraftVersion] |

内部只读投影 `/api/agent-tools/changes/{id}?projection=context` 增补 `source`、`agent_task_id`。

### 边界（不要过度宣称）

- `source` / `agent_task_id` 是**来源标记与关联**，不是授权凭据，也不改变审批、通行证或放行判定。
- Agent 侧关联只建立"任务 → 已存在变更单"的记录；它不代表该变更单已批准或可在生产执行。
- Go 正式变更的来源隔离（评测 / 演示产物不得获得生产放行）在 **M3** 完成；M2 阶段它尚未生效，当时 `source` 只是标记。
- 仍然不宣称外部模型调用 exactly-once；恢复语义继续标记为 at-least-once。

## M3：项目知识与独立评测中心（本批）

- **项目知识导入与版本化**：按组织导入规范 / 历史案例 / 结构快照，可选限定到某个应用；
  记录版本、来源、失效状态、内容摘要与可引用片段。失效（deprecated）保留记录但不进入检索。
- **服务端强制的检索权限过滤**：可见范围由服务端按「组织 + 应用 + 生效状态」判定，且在
  构建检索器时就生效；跨组织、未授权应用与失效知识都不可能出现在结果或证据里。任务工作流
  按任务的 (组织, 应用) 构建检索器，模型无法用参数扩大范围。
- **应用权限来自服务端判定，不是请求参数**：组织内部的应用授权由治理后端
  `/api/agent-tools/applications/{id}` 核对（成员存在、组织一致、应用 view 授权）。
  导入、列表、详情、检索、废弃与任务检索都会先核对；未授权或无法核对一律拒绝（失败关闭）。
  未指定应用时**不返回应用专属知识**（无法逐条核对）。任务只记录"已核对通过的应用"，
  检索不回退到请求里声明的应用。
- **不可信内容**：导入正文只作为数据被检索与引用，不会被当作指令执行，也不提升工具或身份权限；
  命中提示注入模式只**如实记录**为数据风险，既不据此放行，也不据此拒绝一份可能正当的安全文档。
- **独立评测中心**：复用已有 eval harness，提供评测作业、状态、报告查询、并排对照与失败分类。
  评测在**独立工作目录**运行，任务来源强制为 `evaluation`，不向正式存储批量写测试变更。
- **真实模型门禁**：`live` 必须显式启用（`AGENT_EVAL_LIVE_ENABLED=1`）且配置凭据，否则作业记为
  `not_run`；真实模型调用受 `AGENT_EVAL_TASK_TIMEOUT` 与可选 token / 请求上限约束。未运行就是
  未运行，不用离线结果冒充真实模型质量。
- **Go 可信来源与关联约束**：变更来源由服务端判定（`console` / `agent_task`）；放行流程使用
  **失败关闭的来源白名单**——来源不被信任（例如评测 / 演示产物）时，提交、审批与签发通行证
  一律拒绝。幂等重放保留原始来源，调用方无法声明 `source`；`agent_task_id` 支持按任务查询。
- **Agent 关联必须服务端核对**：请求体里的 `agent_task_id` 不得直接决定来源。服务端以**发起人
  自己的身份**向变更准备服务读取该任务（该接口只返回本人、同组织的任务），再核对来源必须是
  `production`、应用一致、草案材料（SQL 与回滚）一致；任一项不满足或无法核对（未配置、不可达、
  非 200、任务不存在）一律**拒绝建立可信关联**。直接调用服务层传入未核对 ID 同样被拒绝。

### 边界（不要过度宣称）

- 结构快照虽可导入并检索，但**尚未**自动注入草案生成；首版仍以任务自带的快照为材料来源。
- 评测的失败分类是粗分类（聚合用），原始错误原文保留在报告里，不能被分类覆盖。
- 评测对照可能跨不同 provider / strategy / 数据集，只陈述差异，不做统计结论。

### M3 部署与回滚边界

- 同时升级 Python Agent 与 Go 服务。Go 的来源白名单是放行路径上的**新增拒绝**：历史记录
  `source` 为空时按 console 处理，不误伤既有变更。
- Agent 镜像新增评测框架与数据集（只读）；知识与评测各为独立 JSON 文件，不影响既有任务存储。
- 回退到旧版本：旧 Agent 不认识知识 / 评测接口，旧 Go 忽略 `source` / `agent_task_id` 字段
  （JSON 兼容）。已导入知识与评测作业保留在各自文件里，但旧版本不读取它们。
- **回退来源白名单会重新允许不可信来源进入放行流程**；回滚必须显式评估这一风险，不能静默回退。
