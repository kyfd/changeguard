# 本机 HTTP 冒烟测量

2026-09-05，基于 `973ff394` 加本次 `fix/portfolio-evidence` 改动，负载工具为同分支 `cmd/loadtest`。这不是容量测试或优化前后对比。

环境：Windows，Go 1.26.3，Intel i7-9750H；Docker Desktop WSL2 分配 12 逻辑 CPU、约 7.7 GiB 内存。Compose 中两个 Go 后端共享 PostgreSQL 16 和 Redis 7.4，另有影子 PostgreSQL。请求固定打到主实例，没有负载均衡。数据库中共 19 条合成变更，开发账号只读取其授权范围。服务与负载发生器同机，机器另有开发服务运行，未隔离 CPU。

命令：先用 `-c 1 -d 2s` 预热，然后按 1、8、32 并发顺序各运行三轮：

```text
loadtest -url http://127.0.0.1:18080/api/dashboard -c <并发> -d 5s -json
```

登录使用本机演示账号，通过 `CHANGEGUARD_LOADTEST_EMAIL/PASSWORD` 注入。连接复用、闭环固定并发、默认 5 秒请求超时，计时到响应体 EOF；每轮登录时间不计入测量。原始报告保存在同目录 `c<并发>-r<轮次>.json`。

| 并发 | 三轮成功请求/秒 | 三轮成功 P95（毫秒） | 失败 |
| --- | --- | --- | --- |
| 1 | 521.3 / 479.4 / 489.5 | 3.10 / 3.03 / 3.02 | 0 |
| 8 | 1357.0 / 1312.2 / 1413.5 | 10.51 / 10.99 / 10.13 | 0 |
| 32 | 1418.7 / 1560.7 / 1294.3 | 38.05 / 33.34 / 42.28 | 0 |

所有响应均为完整 HTTP 200。本实验只确认新统计工具可对真实已认证 GET 生成重复报告。样本很小、每轮仅 5 秒、未采集 CPU/内存/PG 锁等待，不能推导生产 SLA、成功消费写入吞吐或瓶颈成因。1,000/10,000 变更数据集、独立成功写入与锁竞争分析仍待执行。
